# HU-12 · Asistente interno

## Entrega y alcance

El backend está en Tracking-Logistico/Sprint-2. El widget está en el repositorio independiente Tracking-Logistico/tracking-logistico-frontend. No aplicar el parche del frontend a la carpeta homónima que existe dentro del backend.

Gemini clasifica una pregunta anonimizada. El servidor valida primero el alcance y extrae el destinatario de la consulta. Solo envía el prefijo permitido con el marcador OBJETIVO, sin nombre, correo, tracking ni resultados de base de datos. El modelo devuelve una intención de un enum cerrado; debe coincidir con la clasificación local. El servidor ejecuta SELECT predefinidos y construye la respuesta con datos verificados. No hay SQL generado, herramientas de escritura ni respuestas de negocio inventadas por el modelo.

Consultas admitidas incluyen «¿Qué rol tiene Juan Pérez?», «Perfil de persona@example.invalid» y «¿Dónde está el paquete NCA-PRUEBA?». Son ejemplos sintéticos. La búsqueda de usuario es exacta por nombre o correo, sin distinguir mayúsculas. Ante homónimos se solicita el correo. El asistente no conserva contexto conversacional ni resuelve referencias como «¿y ese usuario?»; cada pregunta debe identificar el recurso. Ante duda, múltiples objetivos, métricas, solicitudes de escritura o instrucciones extrañas, responde fuera de alcance y sugiere una consulta válida.

## Roles existentes

Se conserva el modelo actual CLIENTE / OPERADOR / CONDUCTOR, sin agregar Admin. Solo una sesión individual OPERADOR activa y con perfil de operador habilita el endpoint y el widget. Una clave DBA compartida no identifica al consultante y no habilita este asistente. Quien realice tareas administrativas debe utilizar su cuenta interna OPERADOR para esta consulta. Por tanto, el criterio de un rol ADMIN independiente queda condicionado a que el proyecto incorpore ese rol en otra entrega; no se afirma que exista.

El alcance de información es el mismo acceso global de consulta del operador existente. El repositorio no define pertenencia de operadores a oficinas o tenants; no se inventa esa relación. Las sesiones del asistente sí se autorizan por propietario y vencimiento.

## API

POST `/api/v1/assistant/query` en Identidad, accesible a través del Orquestador. Authorization Bearer con token opaco existente. JSON con cuatro campos exclusivamente:

```json
{"texto":"¿Dónde está el paquete NCA-PRUEBA?","sessionId":null,"solicitudId":"12345678-1234-4234-8234-123456789012","origen":"WEB"}
```

El primer envío crea una sesión. Usar su `sessionId` en consultas posteriores durante 30 minutos. `solicitudId` es un UUID nuevo por consulta. Repetirlo para el mismo usuario devuelve 409 y no llama nuevamente al proveedor. Respuesta autorizada con `sessionId`, `resultado` y `mensaje`; resultados RESUELTA, FUERA_DE_ALCANCE o SIN_DATOS. Los fallos se auditan con ERROR y los errores HTTP devuelven texto genérico. Respuestas exitosas tienen Cache-Control no-store.

Sin autenticación devuelve 401. Cliente y Conductor reciben 403. Sesión ajena o vencida devuelve 403. Esquema inválido, campos extra, texto de más de 500 caracteres o cuerpo de más de 4096 bytes devuelve 400. Límite de 30 consultas por usuario/minuto compartido en BD, 429 al excederlo; capacidad máxima de ocho ejecuciones concurrentes. Los límites y la autorización se imponen en backend.

El perfil incluye nombre, rol, estado, correo, teléfono y cédula enmascarada; nunca contraseña, hash, tokens o nacimiento. Los datos HU-13 se descifran únicamente en servidor y se enmascaran antes de salir. La ubicación usa eventos HU-19 y excluye eventos sustituidos por correcciones. La respuesta indica explícitamente si aún no hay ubicación.

## Migración y configuración

Aplicar V29 mediante el Flyway existente de Identidad antes de habilitar el módulo. Añade assistant_session, assistant_query_log, assistant_rate_limit y tres vistas de lectura. La migración no crea contraseñas ni usuarios de BD. El esquema H2 equivalente permite las pruebas del endpoint con lector simulado.

| Variable del servicio Identidad | Valor / propósito |
| --- | --- |
| ASSISTANT_ENABLED | false por defecto; true después de configurar lo siguiente |
| GEMINI_API_KEY | Clave privada del proyecto Gemini, configurada como secreto del entorno |
| GEMINI_MODEL | gemini-3.5-flash-lite por defecto; modificable sin cambiar código |
| ASSISTANT_READ_JDBC_URL | JDBC PostgreSQL al mismo esquema de negocio, con sslmode=verify-full |
| ASSISTANT_READ_JDBC_USER | Login exclusivo de solo lectura |
| ASSISTANT_READ_JDBC_PASSWORD | Contraseña privada de ese login |
| ASSISTANT_READ_REQUIRE_TLS | true en despliegue; false solo con perfil local/test/h2 |
| ASSISTANT_RETENTION_DAYS | 30 iniciales, rango 1–365; pendiente de confirmación del responsable |

Se mantiene la configuración de cifrado HU-13 existente. El lector debe apuntar al mismo esquema que las migraciones, usando currentSchema si no es public. Configurar el certificado raíz de PostgreSQL según el proveedor para verify-full. No desactivar la verificación TLS en producción.

Un DBA debe crear un login nuevo con LOGIN, NOSUPERUSER, NOCREATEDB, NOCREATEROLE, NOREPLICATION y NOBYPASSRLS, sin membresías con privilegios. Asignar la contraseña fuera del repositorio con el mecanismo seguro del proveedor o `\password` de psql. No reutilizar el propietario ni la cuenta de migraciones. Revisar privilegios PUBLIC heredados, en particular CREATE sobre el esquema y SELECT sobre tablas sensibles. La aplicación rechaza cuentas con escritura, poderes administrativos, creación en el esquema o lectura de tablas distintas de las tres vistas.

Desde una sesión DBA conectada al esquema correcto, ejecutar el script de permisos, proporcionando el nombre real del login (no una contraseña):

```powershell
psql $env:DATABASE_URL -v assistant_login=$env:ASSISTANT_READ_JDBC_USER -f .\scripts\assistant_reader_permissions.sql
```

El script solo concede USAGE del esquema y SELECT de las vistas assistant_user_profile, assistant_package y assistant_location. No concede acceso directo a usuarios, pedidos, sesiones o auditoría. La auditoría usa la conexión de escritura existente por separado; no se entrega al clasificador ni al lector de negocio.

En frontend se conserva VITE_API_URL, apuntando al Orquestador, con /api/v1 y HTTPS. Desplegar Identidad y Orquestador actualizados y luego el frontend independiente. La clave Gemini nunca es VITE_* ni se incluye en el bundle.

## Gemini y tiempos

Cliente HTTP de Java existente, sin SDK ni dependencias nuevas de producción. Interactions API v1beta con revisión 2026-05-20, salida JSON estructurada, store=false, sin herramientas, máximo 128 tokens y pensamiento mínimo. Referencias verificadas: https://aistudio.google.com/api-reference/interactions-api/create-interaction y https://aistudio.google.com/docs/structured-output. Si cambia el contrato del proveedor, la validación falla de forma cerrada.

Conexión de Gemini de 2 s y solicitud completa de 5 s; SQL de lectura de 1 s por sentencia y socket de 2 s; procesamiento HTTP con corte a 8,5 s; el widget cancela a los 10 s con mensaje genérico. El chat muestra «Generando respuesta…», escapa texto con React y borra el historial al cerrar o desmontar. No guarda conversaciones en localStorage. La sesión de autenticación preexistente conserva su propio comportamiento.

No se recibió una API key y no se realizó una llamada facturable a Gemini. El contrato HTTP, anonimización, respuestas inválidas, clave ausente y timeout se prueban con servidor HTTP controlado. La latencia real P95 del despliegue requiere ejecutar las consultas con la clave y el servicio activo. Los arranques en frío del alojamiento, red, cuota y disponibilidad del proveedor pueden impedir el objetivo de 10 s; el timeout evita dejar la interfaz esperando indefinidamente. Verificar facturación, cuotas y condiciones del proyecto Gemini antes de activarlo.

## Auditoría y retención

Las tablas guardan identificador interno del usuario, UUID de sesión/solicitud, fechas UTC, intención, resultado y origen. No se persisten preguntas, nombres buscados, correos, tracking, cédulas ni respuestas. El identificador de usuario es un dato de auditoría autorizado, no se considera anónimo. ERROR registra fallos de infraestructura además de los tres resultados funcionales solicitados.

La reserva se registra antes de llamar al proveedor para impedir dobles ejecuciones. Transacciones y bloqueo de la fila del usuario serializan reservas y rate limit entre instancias. Un proceso horario elimina consultas anteriores a la retención, sesiones expiradas sin consultas y contadores antiguos. Una caída puede dejar el resultado ERROR, sin texto sensible. La retención de copias de seguridad y los logs HTTP del proveedor de infraestructura requieren la política operativa del despliegue. No activar logs de cuerpos HTTP, SQL con parámetros ni trazas del cliente Gemini.

## Seguridad obligatoria

| Regla | Cumplimiento y límites |
| --- | --- |
| 1 RBAC backend | Matcher OPERADOR, comprobación de cuenta activa/perfil interno; 403 para roles no autorizados. Pruebas de llamadas directas. |
| 2 Anti-IDOR | Sesión vinculada a usuario y expiración, FK compuesta y prueba de sesión ajena. Acceso a perfiles/paquetes según el alcance global del operador existente. |
| 3 Entradas y SQL | DTO validado, cuerpo limitado, campos permitidos, UUID y enums, guardrail cerrado; PreparedStatement y JdbcTemplate parametrizados. |

| 5 Errores / logs | Advice específico genérico, sin imprimir preguntas ni respuestas. Auditoría solo de metadatos. Revisar configuración externa de logs al desplegar. |
| 6 Datos sensibles | Reutiliza AES-GCM de HU-13; no almacena nuevos datos de identidad, enmascara cédula y excluye nacimiento. Nombre/contacto solo para operador autorizado. |
| 7 Auditoría | Usuario interno, instante UTC, intención, resultado y origen; no existen cambios de estado de negocio. |
| 8 Concurrencia | UUID único por usuario, sesiones con FK de propietario, transacciones y bloqueo, límite distribuido de consultas. |
| 9 Secretos / dependencias | Variables de entorno, ninguna clave en código; sin dependencias nuevas de producción. Playwright 1.62.0 solo para pruebas externas de navegador. |
| 10 TLS / rate limit | Endpoint Gemini fijo HTTPS, lector PostgreSQL verify-full exigido en producción, 30/minuto/usuario. HTTPS del portal/gateway depende del despliegue y debe mantenerse. |
